# ESP32 proof of concept

This example is intended for an ESP32 DevKit (classic ESP32), with no external sensor or LED hardware required. The temperature and humidity values are generated by template sensors, and the RGB outputs are virtual template outputs that log their values.

## Before compiling or flashing

Edit `esp32-basic.yaml`:

1. Replace `REPLACE_WITH_WIFI_SSID` and `REPLACE_WITH_WIFI_PASSWORD` with your Wi-Fi credentials.
2. Change the web interface username and password. The committed values are demonstration placeholders and must not be used on a real network.
3. Review the board and framework settings if your ESP32 board differs from `esp32dev`.

The web server uses HTTP Digest authentication. Keep the device on a trusted network; this PoC does not provide HTTPS.

## Build with ESPHome

From the repository root:

```bash
esphome config examples/esp32-basic.yaml
esphome compile examples/esp32-basic.yaml
```

To flash over USB, connect the ESP32 and run:

```bash
esphome run examples/esp32-basic.yaml
```

After the device joins Wi-Fi, open its IP address in a browser. The browser will ask for the web server credentials.

## What to test

- Temperature and humidity update every five seconds.
- The switch can be turned on and off.
- The RGB color picker sends red, green and blue values to the light.
- State changes arrive through the `/events` Server-Sent Events connection.
- All UI assets are served by the ESP32. The page does not need a CDN or external internet access.

## Implementation notes

ESPHome's version 2 web server builds a small HTML shell containing an `<esp-app>` element. With `js_url: ""` and `js_include`, the device serves our module at `/0.js`; our module defines the `esp-app` custom element and supplies the complete interface. `css_include` serves the stylesheet at `/0.css`.

The example deliberately does not set `local: true`: that option embeds ESPHome's bundled frontend HTML, whereas this PoC uses the configurable HTML shell and local include routes. The empty `js_url` and `css_url` values prevent external asset requests.

The PoC reuses ESPHome's existing API:

- `GET /events`: initial entity states and real-time state updates.
- `POST /switch/{entity}/turn_on` and `turn_off`: switch control.
- `POST /light/{entity}/turn_on?r=...&g=...&b=...`: RGB light control.

The frontend reads `name_id` when present and falls back to `id`, accommodating ESPHome's entity identifier transition.
